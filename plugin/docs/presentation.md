# 后台展示禁用（1.0）

本版沿用原版场景、物品脚本、事件总线及 60 Hz 计时。只修改本地生成的私有计算包，正常游戏和实验室界面不使用这些补丁。没有重建几百种物品的独立规则引擎。

## 禁用入口

`presentation_free.py` 使用明确名单禁用物品激活动作、纯展示的迷你激活、角色动作、飘字、音效、对白、血条/体力条刷新和弹性精灵处理。物品中的一次性粒子调用及后续位置、颜色赋值一起移除，避免返回空对象导致调用方崩溃。未知的粒子返回值用途会使构建失败，要求重新审查。

原版后台仍会将事件转换为战斗日志的富文本界面行，复杂阵容每场可超过千行。1.0 保留 `events` 与 `statLoggers`，停掉界面行预创建、生成和延迟显示队列，统计读取和事件时间戳保持原路径。

这些是经审查的高频入口，不承诺所有场景构造和纯展示属性赋值都已消失。首次仍加载原版场景；结果缓存、固定对象预热和逐场状态复原继续降低连续计算开销。

## 必须保留的规则

- `playOutOfStaminaAnimation` 保留体力不足次数累加。
- `activate` 保留同帧触发上限、激活事件、统计和冷却快照，去掉动作尾部。
- Falcon Blade 的两次伤害、Ruby Chonk 的眩晕和状态改变均保留。
- 电荷仍是原版对象，入格、离格、受电与回收回调沿用原版 SceneTreeTween 调度器、回调顺序与时间；只移除位置插值、渐变、粒子和电弧。不会统一杀掉全部计时器和补间。
- 疲劳开始、增长、先后受伤次序和下一跳计时保留；原版统计日志仍采集。

## 验证

`test_reuse.py` 在六职业、木桩/对手两模式下检查冷建、复用、重复、删物品、放回物品及预热。`test_presentation.py` 逐场比较旧版本的种子、胜负、时长、双方曲线、物品统计和剩余血量；附带只存在于测试包中的对象池调用计数，检查复杂工程师战斗期间只创建规则所需电荷，不创建飘字和粒子对象。

`test_common_random.py` 验证无联动的小猪罐变动和精确 +15 护甲差值，并检查禁用体力动画仍累加计数。`test_frontend.py` 验证真实界面流程与后台结果衔接。以上属于本地回归覆盖，不等于所有可能阵容已穷举，也不等于预测线上实际随机种子。
