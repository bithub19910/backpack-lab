# 阵容比较与固定随机样本

1.0.0 将同一组随机样本用于前后阵容的配对比较。默认十场仍各有不同的种子；重复重算使用同一组。没有后台换种子复核，也不在界面显示“零误差”或抽样误差百分比。

只固定一个全局种子不够：新增物品、数组次序、动画调用都可能提前消耗随机数，使其他物品拿到不同的暴击或伤害样本。实现为：

- 为活体物品分配稳定身份，移动、旋转和取下重放保留身份，快照与商店预演传递身份。
- 输入及场景节点使用规范次序；相同原版触发优先级内，以种子和稳定身份产生固定顺序。增加无战斗作用的物品不会重新洗牌其他物品。
- 按场次、物品身份、用途分配随机流。伤害、冷却、概率特效与视觉随机数分开。
- 角色的命中、暴击和抗性继续使用原版 BalancedRng 的平衡计数，但随机输入固定；状态抵抗、反射、净化保护使用独立战斗随机流。
- `cosmetic_random.py` 按经审查的方法名单分离对白、商人反应、商品动画、飘字、声音、装饰和粒子随机调用。混合方法仅替换展示表达式，不改变商店抽取、生成物品及匹配逻辑。角色自动战斗狂怒的候选选择与状态溢出同值排序也不再走全局随机通道。
- 私有计算进程复用对象前恢复战前状态，再重置本场随机流。实际游戏进程不应用这些随机补丁。
- `presentation_free.py` 在上述隔离基础上禁用经过审查的高频展示入口；不会全局停用 Timer/Tween。电荷传播等使用补间调度的战斗回调仍保持原顺序和时刻。详见[展示禁用边界](presentation.md)。

这保证的是在已验证条件下，前后比较不被无关随机调用扰动，不代表十个样本等于所有可能战斗的真实期望，也不复现线上对局的实际随机种子。新物品改变攻击次数、生存时间、邻接和连锁触发时，差值仍可能随战斗产生真实变化。

## 回归验证

`test_common_random.py` 在原版引擎中创建不含额外联动的固定测试阵容，清除结果缓存再执行：小猪罐新增、取下重放、四种移动/朝向，逐场比较五条统计曲线；新增 Protective Purse 要求每场累计护甲精确增加 15、伤害曲线不变。15 秒窗口对应每秒回复增加 1。另检查十场仍有不同伤害结果，防止误将所有场次变成同一场。

`test_reuse.py` 比较完整重建与对象复用，包括重复计算、删除及放回物品。它依赖本地历史阵容，不能在无正版游戏的公共 CI 中执行。测试原始阵容、运行日志及游戏派生文件不进入源码包。

额外检查直接调用原版商人对白、人物音效、商品粒子和飘字方法前后，两种全局随机源的状态均不改变；测试专用计算包还会在战斗每帧插入展示随机调用，要求十场配对曲线完全一致。该注入开关只存在于测试包，不进入发布计算组件。

## 界面与本场胜率

两个图表最小高度跟随自身宽度，默认剩余空间优先分配给图表。设置、统计等下方内容动态展开；空间不足时在下方区域滚动，保留主图。

正式对战开始时冻结双方阵容并提交 25 场后台计算，同步保存最近对手。结束事件只控制结果显示，不重复提交。计算中仅显示“计算中”；默认结束后展开，可用眼睛提前查看已完成结果或隐藏，并保存偏好。进入下一商店隐藏该浮窗。
